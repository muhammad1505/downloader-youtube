# Karaoke on-device — TubeFlow 1.1.6 (20)

## Masalah dan keputusan

L/R hanya volume kanal, sehingga tidak bisa memisahkan vokal pada campuran biasa. Karaoke memakai UVR-MDX-NET-Inst_HQ_3 (instrumental), ONNX Runtime CPU1.23.2 dan FFmpeg yang sudah ada. Model diunduh opsional; audio tidak dikirim ke server. Tidak ada engine player kedua, database baru, atau perubahan audio sumber.

Model asli66759214byte dengan SHA256 `317554b07fe1ea5279a77f2b1520a41ea4b93432560c4ffd08792c30fddf9adc`. Dua deklarasi dimensi waktu dan panjang pesan protobuf diubah256→64 untuk mengurangi RAM, tanpa perubahan tensor terlatih. Ukuran hasil66759212byte. SHA256 hasil `bf09aee9b867a102c786dd8205d7f5176938b78329d906773764e05918d21c4f`. Patch byte hanya dijalankan setelah hash/ukuran asli cocok; hash hasil juga wajib cocok.

Parameter dari [registry UVR](https://github.com/TRvlvr/application_data/blob/3826b05b570dbd4fbedbc807758803b35348ba1b/mdx_model_data/model_data.json): FFT6144, hop1024,3072bin, kompensasi1.022, targetInstrumental. Kredit/lisensi dari [pernyataan developer UVR](https://github.com/Anjok07/ultimatevocalremovergui#license); teks MIT2022 dipertahankan dari revision0fd6b751dbbe9da9c96660d0b4ec2b07108727b7. [ONNX Runtime](https://github.com/microsoft/onnxruntime/blob/v1.23.2/LICENSE) MIT. Notices/lisensi dibundel di `assets/notices/`.

## Alur dan batas

Putar audio selesai → tombol mikrofon dicoret **Karaoke · Pisahkan vokal** di mini/full player. Uji cuplikan30detik dimulai dari posisi pemutar (dibatasi agar masih ada audio); matikan pilihan cuplikan untuk seluruh lagu. Satu job WorkManager, foreground notification/progres/batal. Tutup dialog tidak membatalkan proses. Ikon karaoke topbar membuka status/hasil kembali.

Batas awal: proses64-bit, audio≤10menit, input≤256MB, RAM tersedia≥512MiB, ruang sementara diperiksa, tidak ada unduhan aktif saat mulai. Inference CPU2thread, perpotongan, tidak memuat seluruh PCM ke RAM. Hasil FLAC stereo44.1kHz/16bit merupakan media turunan; kualitas/format sumber tidak diubah. Hasil bisa menyisakan vokal/artefak dan bukan jaminan100% bersih.

Dengarkan dulu lalu pilih Simpan. MediaStore/SAF memakai tujuan pengaturan saat simpan dan nama baru `(Karaoke)` atau `(Karaoke cuplikan)`, tanpa overwrite. Hash baca ulang diverifikasi, pendingURI dijurnal, indeks Room yang sama diperbarui. Lagu penuh mendapat salinan LRC sendiri jika tersedia; cuplikan tidak memakai lirik penuh. Proses ini bukan download historis baru.

Input/PCM sementara dibersihkan; model serta pratinjau terakhir tetap privat. Proses baru secara eksplisit mengganti pratinjau privat lama, bukan file publik. Cancel menghentikan session/prosesFFmpeg milikjob; job baru menunggu cleanup lewat mutex. Proses mati dapat memulai ulang dengan aman, tetapi belum melanjutkan inference perpotongan.

## Bukti sementara

Host: model standar satu input256frame sekitar1251MiB RSS; deklarasi64frame menurunkan konsumsi. Cuplikan SATRU2 lokal detik90–102 berhasil dipisahkan menjadi FLAC12detik. Prototipe NumPy/ORT1.23.2 dengan64frame memakai434MiB RSS puncak,62.44detik saat Gradle berjalan bersamaan; bukan benchmark HP atau bukti kualitas auditori. Perubahan waveform/RMS membuktikan pemrosesan, bukan vokal hilang seluruhnya.

78tes Python lulus. Build pertama menemukan API CoroutineWorker.onStopped final; diperbaiki memakai childcoroutine pembatalan agar native/FFmpeg dapat dihentikan. Tes pertama HP berhasil mengunduh model dan memverifikasi hash, lalu gagal pada linkerFFmpeg karena libc++_shared.so berada di paketPython. JalurLD_LIBRARY_PATH diperbaiki mengikuti direktori runtimeyt-dlp, termasuknativeDir. 61/61hash media lama tetap sama sesudah gagal. ORT1.31.0 probe menunjukkan callbacktelemetriJNI tidak tersedia padaHP; kandidat menggunakan1.23.2 tanpa initprovidertelemetri Android, dengan telemetry dinonaktifkan secara eksplisit.

Build/unit/lint final dan uji HP masih berlangsung; hasil di bawah diisi hanya dari eksekusi nyata.
